# Learning

Read before touching `features/learning/`.

- **Learning** (`features/learning/`, routes `…/w/:id/learning`, `…/learning/progress`, `…/learning/:lessonId` with `lessonLoader`):
  - Structure: `learning_modules` → `lessons` → `lesson_progress` (a lesson marked done by a user). A lesson's content lives in its folder in Files (below); `lessons.body` is unused and unwritable since 2026-10-27 (drop it once no older tab is open).
  - Positions: new items go last (trigger), and moving a lesson to another module puts it last. Reorder with `rpc('reorder_learning_modules')` / `rpc('reorder_lessons')`.
  - Access: managers edit the outline; everyone in the workspace reads it. You mark and unmark only your own progress; managers read everyone's (Class progress).
  - `useLearning()` gives the outline in reading order, your done set and the next lesson.
  - **Lesson files** (2026-10-27, owner's choices; `20261027090000_lesson_files.sql`, replacing the 2026-10-25 lesson boards): lessons keep their content the way plans do. The course's Files has a **Lessons** folder (`doc_folders.is_lessons_root`) with one folder per lesson (`doc_folders.lesson_id`, named after it, "Recap (2)" when two share a title, renamed with it), holding the doc **Lesson** (`lessons.doc_id`, its text), its **Whiteboard** (`lessons.whiteboard_id`, made when a teacher clicks Start: `rpc('lesson_whiteboard')`) and whatever teachers add with the lesson page's +. Existing lessons were moved in by the migration (text → doc, old board → folder). Files inside carry `lesson_id` (set from the folder by `set_file_lesson`; it cascades, so deleting a lesson or module deletes its files; the app removes their images first via `rpc('lesson_doc_ids')`).
    - **Who:** only the course's managers change lesson files: `private.file_level` holds everyone else to view (1) inside the Lessons folder (`private.in_lessons`), so docs, whiteboards, images and moves all follow. Lesson folders are protected like plan folders (`protect_lesson_folders`, DD003; `followsItsOwner` in `DocBrowser`).
    - **Where students see them:** only on the lesson page (owner's choice). Files leaves the Lessons folder (`withoutLessons`) and files with `lesson_id` out for anyone who doesn't manage that workspace (`useCanWriteDocs`); RLS still lets them read, because the page needs it. Teachers see the folder in Files.
    - **The page** (`LessonView`): tabs **Lesson | Whiteboard | each other file** (`?tab=whiteboard`, `?file=<id>`), all ordinary editors embedded: `DocView embedded` (no Files path, author or delete; `withTitle` for the extra docs) and `DiagramView embedded` (lazy `LessonBoard`). `lessonQuery` brings the lesson, its Lesson doc whole (with `access_level`) and its folder's other files in **one request**; `lessonLoader` puts the doc in `documentQuery`'s cache, so opening a lesson costs no extra round trip and live updates reach it as for any doc. Doc tabs stay mounted (hidden) once opened, so switching tabs never drops an edit; whiteboards save when they unmount. Realtime refetches a lesson only when a file is **added** to its folder (`lessonFileAdded`), never on autosave.
