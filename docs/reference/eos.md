# EOS (the Ninety sync)

Rules for `features/ninety/` and the `ninety-sync` function; the full record is `docs/NINETY.md`.

- **Ninety (EOS) sync** (`features/ninety/`, the `ninety-sync` Edge Function; full record in `docs/NINETY.md`, read it before touching either). One way, DevDock → Ninety, behind the `ninety_sync` flag. Phase 1 (2026-10-28): assigned issues in a linked project's **running sprint** become Ninety **To-Dos** (owner matched by sign-in email, else the connection's fallback owner with "(for Name)"; Done/Canceled or leaving the sprint completes it; deleting deletes it). Phase 2 (2026-10-28): **plans with a target date become Rocks** in the group's chosen Rocks team, their **dated issues become Milestones** (Ninety can't delete one: it is completed and marked "(removed)"), and To-Dos are linked to their plan's Rock. Phase 3 (2026-10-28): issues **labelled IDS** (every linked project gets the label) become Ninety **Issues** for the weekly meeting. **Group → Ninety** (sidebar, flag only; `NinetyPage`) shows what is in Ninety now, read live in one request (the function's `overview`), each item with a chip to its DevDock issue or plan; anyone in the group, minus items from issues they can't open. It has no route loader and no hover prefetch on purpose (each cost every first load ~1 KB). Headlines and Scorecard are skipped for now.
  - Group settings → Ninety (`NinetySection`, owners/admins of flagged groups): the token goes to the function, which keeps it in **Vault**; clients can read only the granted columns of `ninety_connections`, never the token. Projects link to Ninety teams through `rpc('ninety_set_workspace_team')`.
  - Triggers queue changed issues in `ninety_outbox` only for connected, flagged groups; pg_cron `ninety-sync` calls the function **twice a day (00:00, 12:00 UTC)** when the outbox has work (pg_net, Vault secret `x-ninety-cron`); the owner ruled out an every-minute job, so anyone in the group sends what's waiting with **Sync now** on the Ninety page; `ninety-sprint-edges` queues sprints that start or end. The function records its own URL on first connect (`ninety_config`), so nothing is set up by hand per project. `plan.ts` holds the rules (pure; `npm run test:ninety`).
  - Supabase's API refuses UPDATE/DELETE without a WHERE (pg-safeupdate), also inside functions called through it: keep a WHERE even on single-row tables.
  - Tests: `supabase/tests/ninety_sync.sql` (50 checks; Dev or local, rolls back).
