# Files: docs, whiteboards and folders

Read before touching `features/docs/` or `features/diagrams/`.

- **Docs editor** (`features/docs/editor/`, page body `features/docs/components/DocView.tsx`, lazy-loaded by `routes/DocPage.tsx`):
  - Extensions are listed in `extensions.ts`, and the typography lives in `styles.ts` as Tailwind classes (no global CSS).
  - `documents.body` (TipTap JSON) is the source of truth; `content` is a plain-text copy written with it.
  - Images are the custom `docImage` node, which stores a Storage **path** (`<team>/<doc>/<uuid>.<ext>`), never a URL; the view signs it (`docImageUrlQuery`). Upload with `uploadDocImage`. `deleteDocument` removes the doc's image folder first.
  - Collapsed headings are per-viewer plugin state (`CollapsibleHeadings.ts`), never saved.
  - **Links to docs and diagrams** (`FileLink.ts`, `FileLinkView.tsx`, `FileLinkPicker.tsx`; in docs, issue descriptions and lessons, which share these extensions): an inline atom `fileLink` storing only `kind` (`doc`/`diagram`) and `id`, never a title. Made by typing `[[` (the picker: ↑ ↓ Enter/Tab, Esc dismisses until the `[[` is retyped; Enter waits while the list loads), the + menu's "Link a doc or diagram", or pasting a DevDock doc/diagram URL (not inside code blocks). The chip shows the current title from `teamDocsQuery`/`teamDiagramsQuery` (one cached, live query per kind, shared with Files: a doc full of links costs at most two requests), opens the item (staying in the workspace when it's that workspace's), and shows "Doc/Diagram you can't open" without a title when the reader can't see it (RLS) or it's gone. `renderText` writes `[doc]`/`[diagram]`, so `documents.content` never carries a linked title. Links, not embeds (owner's choice). Next: "Convert to diagram" on Mermaid code blocks, then "Linked from" on the diagram page.
  - Don't add paid TipTap extensions.
- **Doc folders** (`doc_folders`, `features/docs/{folders.ts,components/DocBrowser.tsx}`). **Shared folders** (2026-10-24): folders hold docs **and diagrams** (`diagrams.folder_id`, same scope rule, `check_diagram_folder` trigger), on one page called **Files** (owner's choice, replacing separate Docs and Diagrams items; layout settled with the owner on 2026-10-24 after two rounds). `FilesView` (`features/docs/components/FilesView.tsx`) is the page on the group (`TeamDocsPage`) and in a workspace's Files tab (`WorkspaceDocsPage`, the workspace fixed as the place). **Chips pick the view** (`?view=`): Recent (the 25 newest), **Folders** (`files` in code; default: one place's folders, then a "Not in a folder" section for loose docs and diagrams, so nothing ever hides; inside a folder, its subfolders, docs and diagrams; the folder path starts with the place's name, `rootLabel`; a folder's Updated is the newest change inside it, subfolders included, `folderChanged`), Docs, Diagrams (flat lists; in one place each row says its folder, "in Week 1"; Everywhere shows a Where column). A chip shows only where its tool is on. **A Place dropdown at the right of the page header** (`FilesView`'s `header` prop) picks where (`?in=`, group page only): Everywhere (lists only; Files then opens Group-wide), Group-wide (default for Files), or a workspace in the collection view with Files. Moving, folders and drag and drop live in the Files view; "New" in a list makes that kind at the top of the place (group-wide fixed via `groupWide`, Everywhere asks where). Everything reads the group lists `teamDocsQuery`/`teamDiagramsQuery` (shared with link chips, live) plus the place's folders (loaded on pick, prefetched on hover); `filesLoader` prefetches both lists and the place's folders. The workspace-only list queries were removed. `DocBrowser` (the Files view of one place) has **no kind filter** (a Docs/Diagrams filter there hid a new folder, which confused the owner): a place shows its folders, docs and diagrams together, told apart by icon and the "Doc"/"Diagram" line. One toolbar (left: "12 files · 4 folders", or the folder path with drop targets inside a folder; right: an instant search across the place's folders that says where each result lives, and one "New ▾" with Doc for editors, Diagram and Folder for writers), a sortable column header, rows on one grid (`fileGrid.ts`: icon that becomes a checkbox on hover/selection | name + kind or folder summary | owner | updated | actions), and the selection bar replacing the toolbar while selecting. Anything created appears where it was made. Every doc and diagram row (Folders, Docs, Diagrams, Recent) has the same ··· for writers (`FileRowActions`): Move to… a folder of its own place (undoable; folders are loaded on demand when looking Everywhere) and Delete (asks first). Rows carry `data-file-row` for tests. The workspace tab shows when either tool is on (`hasFiles`, `WorkspaceToolGate tool={['docs','diagrams']}`); each kind shows only where its tool is on (`docsEnabled`/`diagramsEnabled`), but the scope's docs are loaded even where Docs is off, because deleting a shared folder deletes the docs inside too. A workspace with the Diagrams tool off reads `noDiagramsQuery` (answered locally, no request). Nav items can name a second path that counts as active (`NavItem.also`, `isNavActive`): Files is highlighted on a diagram's page. Both Files pages are lazy routes (they freed 2.4 KB of first-load JS); `filesLoader` (`features/docs/loaders.ts`) starts their queries alongside the chunk, so opening Files is one parallel round (chunk + documents + folders + diagrams), not a waterfall. Keep new Files data in that loader. The diagram page shows its folder path (folders fetched only when it's in one). Links from docs to diagrams and "Convert to diagram" are the next steps (plan agreed: link chips, not embeds):
  - **Restricted docs, whiteboards and folders** (owner's request, 2026-10-26; migrations `20261026171024_restricted_files`, `20261026173817_file_access_level`): each has `access` `place` (default: everyone who can open its group or workspace) or `restricted` (its maker, the people it's shared with in `file_shares` as viewer or editor, and group owners/admins, who always see everything). A restricted folder restricts everything inside it except what's shared directly. Chosen when creating (`AccessChoice` in `CreateInScopeDialog` and the New folder dialog) and changed in `ShareDialog` (row ··· "Share…", or the header's Share/Restricted button), by the owner or an admin only (trigger `check_file_access_change`); people can only be added if they can open the place. One function, `private.file_level()` (0 none, 1 view, 2 edit by share, 3 the usual role rules), backs every rule: reads, writes, doc images, `move_folder_items`, the folder triggers, and `check_folder_delete` (nobody deletes a folder holding a restricted one they can't open, since its docs would otherwise fall to the top level). Pages read the caller's level with the item (`access_level`, a computed column; `overrideTypes` because the generated types can't see it) so a viewer gets a read-only page. Lists hide what you can't open (RLS) and show `RestrictedMark` on restricted rows. `file_shares` is live (`AFFECTS`). Re-runnable check: `supabase/tests/restricted_files.sql` (42 checks; run it against dev or local after touching any of this, with `workspace_access.sql`). Not built: an "everyone in the group" level, public links, and lesson drafts.
  - **Access:** everyone who can read docs in a scope creates and edits them, including inside folders (`private.can_edit_document`, `useCanEditDocs`). Deleting docs, moving them between folders (checked in `check_document_folder`) and managing folders stay with writers: group owners/admins and workspace leads (`private.can_write_document`, `useCanWriteDocs`, which Diagrams and Live also use).
  - Folders are per scope (group-wide or one workspace), nest **at most 3 levels** (DB trigger sets `depth`), and use the writer rules.
  - The open folder is `?folder=<id>`; `documents.folder_id` must be in the doc's scope (trigger).
  - **Moving** (writers only): docs, diagrams and folders move by drag and drop, by "Move to…", or together as a multi-selection (checkboxes, Ctrl/⌘-click, Shift-click, Select all). The browser follows file-manager habits: dragging an unselected row drags just it, dragging a selected row drags the whole selection, hovering a folder for ~0.8s while dragging opens it, the path above is a drop target, and every move has an Undo toast. All moves go through `rpc('move_folder_items')` (`moveFolderItems`; `move_doc_items` keeps its arguments for older tabs and hands over to it), which is atomic and checks scope, no cycles, the 3-level limit (counting what's inside a moved folder) and sibling names; `dragDrop.ts` mirrors those rules (`dropBlocker`) to decide which targets light up. Don't change the selection or the layout inside `dragstart` (it cancels the drag; the styling is applied a tick later). HTML5 drag and drop doesn't work on touch screens, so "Move to…" stays.
  - Delete folders with `deleteFolder()`, which deletes the docs inside first so their Storage images go too, then the diagrams inside (one request); subfolders cascade. A diagram or doc whose folder disappears any other way drops to the top level (`on delete set null`).
- **Diagram editor** (`features/diagrams/editor/`, page body `features/diagrams/components/DiagramView.tsx`, lazy-loaded by `routes/DiagramPage.tsx`):
  - `model.ts` is the saved format: node types `shape`/`icon`/`container`, edge type `connector`. `serialize()` saves only content (no selection or measurements), and `parse()` validates stored JSON. Colors are stored as keys (`colors.ts` maps them to Tailwind classes, so diagrams work in both themes). Icon keys in `icons.ts` are saved, so never rename one.
  - Layers: React Flow runs with `zIndexMode="manual"`. Containers sit below connectors, and connectors below shapes. `normalizeOrder()` keeps parents before children and sets the z-indexes, so call it after any reorder or reparent.
  - Undo is snapshot-based (`useHistory`). Call `snapshot()` *before* every change.
  - **Blocks** (node type `block`, `BlockNode`): heading, paragraph, bullet list and database table. They grow with their text: no stored height (`serialize` omits it, `parse` ignores it), and only the width is resized (`NodeFrame widthOnly`). The heading is `data.label`, the rest `data.body` (one bullet or table row per line; a row is `name type PK|FK`, `parseColumn` in `blocks.ts`). Double-click the heading or the body to edit it; a body edit takes Enter as a new line and ⌘/Ctrl+Enter to finish.
  - **Clipboard:** copy, cut and paste use the system clipboard through `copy`/`cut`/`paste` events (not keydown), so a copy can be pasted into another diagram or tab. The text is `devdock-diagram/v1` + the saved JSON + the copying editor's id; a paste goes through `parse()` (never trusted), gets new ids, and lands offset in the same editor or in the middle of the view in another. Text fields keep the normal clipboard.
  - **Snap to grid** (16 px, toolbar toggle, remembered in localStorage): new shapes, drags, resizes (`resized` on resize end) and arrow-key nudges all land on the grid, and while it's on the canvas shows graph paper: lines every 64 px in the `--border` hairline color, plus fainter 16 px lines only when **Fine grid lines** is ticked (the properties panel's Canvas section, shown when nothing is selected; also remembered in localStorage). With both drawn, the top `Background` has `bgColor="transparent"` or it hides the one under it and switching it shows a toast saying what changed, because nothing on the canvas moves when it's switched.
  - **Cloud icons** (`cloud.ts`, `cloud-icons/`, see its README): a curated set of the official AWS (37), Azure (30) and Google Cloud (33) icons, merged into `ICONS` as keys `aws-…`/`azure-…`/`gcp-…` (saved: never rename). Drawn as images in their own colors (never tinted or distorted, as Microsoft requires) and labelled with the full service name; each file is its own asset (`?url&no-inline`), fetched only when shown. They aren't listed in the shape panel: they show when searching ("lambda", "aws"), and in **Recently used**, the panel's top section: the last 9 items added by click or drag, newest first, per browser (`recent.ts`, localStorage `devdock-diagram-recent`, validated on read like a drop is). The Data section also has a **Schema** preset (a dashed container titled "public schema").
  - **Mermaid import** (`mermaid/`, `MermaidImportDialog`): Mermaid flowcharts and ER diagrams become ordinary shapes, by pasting on the canvas (bare code, or a chatbot reply with a ```` ```mermaid ```` block) or with the toolbar's **Import Mermaid** dialog (a live preview on a read-only canvas drawn by the editor's own components, shared through `flowTypes.ts`; it needs `ConnectionMode.Loose` like the editor or React Flow drops every connector). Other Mermaid types (sequence, class, Gantt, …) are recognised and refused with a message. `detect.ts` (`findMermaid`) runs on every paste and is tiny; `parse.ts` (text → graph) and `layout.ts` (graph → saved JSON, dagre) load only when importing. The result goes through `parse()` and `paste()` like any clipboard content: one undo step, selected, centred, then the view fits it. Subgraphs become containers, ER entities table blocks (`name type PK FK` rows) with the cardinality in the connector label, `classDef`/`style`/`linkStyle` colors the nearest color key. Links back against the flow (retry loops) leave and enter by the same side so they run around the shapes, not through them. Left/right order of branches comes from dagre and can differ from Mermaid's own renderer. Lines it can't read are left out and quoted in the toast, never fatal. Limits: 300 shapes, 600 links. `parse.ts`/`layout.ts` import each other with `.ts` extensions and nothing from `@/`, so Deno tests run them (`npm run test:mermaid`); keep it that way. Sizes in `layout.ts` estimate how `ShapeNode`/`BlockNode` draw labels: change them together.
  - **Free drawing** (`ink.ts`, `InkLayer.tsx`, `InkNode.tsx`): toolbar tools Select (V), Pen (P; 6 colors, 3 sizes), Highlighter (H) and Eraser (E, rubs out whole strokes); Esc returns to Select; the colors and pen size are remembered per browser (`devdock-whiteboard-ink`). Each stroke is an ordinary node of type `ink` (`data.ink`: tool, size, `pressure`, flat `points` relative to the node, rounded, at most 3000; `stroke` is its color), so it moves, copies, pastes, undoes and autosaves like a shape and `parse()` validates it (bad numbers drop the stroke). Only the drawn line takes clicks (`style.pointerEvents: 'none'` on the node, `visiblePainted` on the path), so a circle drawn around shapes doesn't swallow clicks meant for them. Highlights tint instead of covering: `mix-blend-multiply dark:mix-blend-screen` on the node itself (each node is its own layer, so a blend inside it does nothing). While a drawing tool is on, `InkLayer` covers the canvas and does pan and zoom itself (scroll pans, pinch or ⌘/Ctrl+scroll zooms, two fingers on touch), because it hides React Flow's own handlers; a stylus's real pressure is kept, a mouse's is simulated. Edits are still one person at a time (the typing lock), and others see strokes after the autosave, not live.
  - **Connectors** start and end on the shape's border (`onBorder`: React Flow measures from the outside of the 10 px connection dot), and the arrowhead and corner offset shrink with the gap (`arrowSize` in `connector.ts`).
