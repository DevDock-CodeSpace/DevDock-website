# Platform admin and feature flags

Read before touching `/admin`, `features/admin/`, `features/flags/` or adding a flag.

- **Platform admin and feature flags** (owner's choice, 2026-10-27; migration `20261027110000_platform_admin_and_feature_flags.sql`):
  - A **platform admin** runs DevDock itself (`public.platform_admins`; today only `super@admin.com`). It is in **no group** and is never added to one: `/app` and `/onboarding` send it to `/admin`, and group pages are a 404 for it like for any outsider. Rows are added by a migration or by hand in SQL, never from the app. `private.is_platform_admin()` is the one place it's decided.
  - The **console** (`/admin`, `routes/admin/`, one lazy chunk through `routes/admin/index.ts`: one chunk per page made the bundler regroup shared code and cost everyone ~4 KB): Overview (totals, sign-ups per week), Groups, Users, Feature flags. It reads only through `admin_overview`/`admin_groups`/`admin_users`/`admin_feature_flags` (security definer, `private.require_platform_admin()`, 42501 for anyone else), which return **counts, names, emails and dates, never group content** (owner's rule). Every existing policy is unchanged, so the admin can't read chats, docs or issues. Page loaders start their data only after the admin check (`prefetchForAdmin`), so a non-admin makes no refused requests. Keys `['admin', …]` (`adminKeys`), not live: the console refetches when opened and after its own changes.
  - **Feature flags are per group**: `feature_flags` (key, description, `default_enabled`) and `team_feature_flags` (a group's own on/off). Only platform admins change them (`admin_set_flag_default`, `admin_set_team_flag`; null = follow the default). Clients can't read or write the tables (RLS, no grants).
  - **Adding a flag**: insert its row in a migration and add the key to `FEATURE_FLAGS` (`features/flags/flags.ts`). In the app, `useFeature('key')` (UI only); on the server, `private.feature_enabled(team, key)` (an unknown key is off). Group owners can't switch flags (owner's choice).
  - The app gets a group's flags as the computed column `teams.enabled_features` inside `myTeamsQuery` (`TeamMembership.features`, also on `useCurrentTeam()`), so flags cost **no request**; it returns `{}` to anyone outside the group. Changes reach open tabs when the groups list next refetches (reload, or 10 min stale), not live.
  - **Flags today:** `ask_devdock` (Ask DevDock, the AI: DevDock's special feature, owner's choice 2026-10-27; everything else is part of every group). Off for new groups; every group that existed on 2026-10-27 was given its own "on" (migration `20261027120000`). `AppLayout` hides the button and its ⌘K, and the `ai-agent` function refuses the group with 403 `not_enabled` (`buildContext` reads `enabled_features` in the membership query it already made). `ninety_sync`: the Ninety (EOS) sync (below).
  - Tests: `supabase/tests/platform_admin.sql` (58 checks; Dev or local, rolls back).
