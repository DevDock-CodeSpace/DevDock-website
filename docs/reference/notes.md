# Notes (code: reminders)

Rules for `features/reminders/`; the full record is `docs/REMINDERS.md`.

- **Notes** (`features/reminders/` — the code still says reminders; full record in `docs/REMINDERS.md`):
  - **They live only in the header's Notes panel** (owner's choice, 2026-10-26): no sidebar item and no page. `?note=<id>` on any page opens the panel at that note (`NotesButton` reads and drops it; `?note=open` just opens it); the old `/t/:teamSlug/reminders?r=` address redirects to Chat that way. The panel has Notes, Done, and Archived on request; the last section shown loads more as you scroll. Rows are stacked for its narrow column (title and text up to two lines, then time · issue · workspace). The `reminders` entry stays in `getTeamNav` though the sidebar doesn't show it: removing it regrouped the build's chunks (+7 KB first load).
  - One feature: a **note** is private text, and **optionally** has a time (`remind_at`, nullable since 2026-10-19). Reminders and notes were merged because two overlapping things confused people; there are no meeting-attached notes (that was built and dropped the same day).
  - Private to their owner: RLS is `user_id = auth.uid()` for every operation, and group admins can't read them. Group-scoped, but **not narrowed by the collection view** (personal, like Messages). Reached from the **header button beside Ask DevDock** (`NotesButton`, lazy `NotesPanel`; loads nothing until opened).
  - The rules are in the database, so the app and the AI agent go through the same ones: `private.check_reminder` (the workspace and issue must pass `can_view_workspace`; an issue sets the workspace; changing the workspace drops the issue; a status change stamps `completed_at`/`cancelled_at`; moving `remind_at` later, or clearing it, clears `notified_at`, which re-arms it), plus column grants (no `user_id`, `notified_at` or delete). Status in the UI: open / **Done** (`completed`) / **Archived** (`cancelled`); archive instead of deleting. Leaving the group deletes them (FK to `team_members`).
  - Delivery: the pg_cron job `fire-due-reminders` runs `private.fire_due_reminders()` every minute. It claims (`skip locked`), marks `notified_at` and inserts a `notifications` row (kind `reminder`, dedupe key `reminder:<id>:<epoch>`) in one statement. A note with no time never fires. There is no Edge Function. `purge-cron-history` trims `cron.job_run_details` daily.
  - **When a note's time comes** (`NotePopups`, mounted in `AppLayout`; owner's choice 2026-10-26, replacing a corner toast): it reads the bell's own query (no extra request), and for each fresh (under 12 h) unread `reminder` notification not yet handled in this browser (localStorage `devdock:notePopupsShown`) it **opens the Notes panel** at the newest (`openNotes` in `openNotes.ts`, a window event, so no URL change re-runs loaders). Opened this way the panel is **quiet**: `modal={false}`, no overlay, focus left where it was (someone may be typing), and clicking the page doesn't close it; X or Esc does. It only happens while DevDock is open; the bell has it either way.
  - **The panel** (`NotesPanel`, owner asked for a fresh design 2026-10-26): a write box pinned at the bottom like Chat's composer (`NoteComposer`: Enter saves, first line = title, rest = text; "Remind me" offers `quickTimes` or carries the text to `ReminderDialog` via `draft`), then the open notes split client-side from one list (`PendingNotes`): **Due now** (time passed: cards with Done and Snooze 10 min / 1 hour / Tomorrow, `useSnoozeNote`, which also marks its bell notification read from the cached list), **Coming up** (a timeline by day, time on the left), **Anytime** (no time: small cards, two columns), then **Done** folded (Archived inside). Shared bits: `NoteMenu`, `NoteContext`, `useChangeNoteStatus`.
  - The bell embeds `reminder:reminders(title, notes, workspace_id, issue:issues(number))` and opens the issue, or the Notes panel at that note (`?note=<id>`). Completing or archiving marks its notification read (trigger).
  - New note dialog: "Show this note to me at a set time" is a checkbox, off by default (on when opened from an issue's note button). Pending notes sort by time soonest first, notes without a time after, newest first.
  - Status changes are optimistic, and `useSetReminderStatus` returns a promise: the row unmounts as it changes section, and TanStack skips `mutate()` callbacks for an unmounted component. Keep toasts on the promise.
  - The issue page's note button mounts `ReminderDialog` only while it's open (no requests). The dialog's issue picker loads `['reminders', 'issue-options', ws]` only when opened (in `NOT_LIVE`).
  - Ask DevDock tools (`ai-agent/tools/reminders.ts`, names unchanged): the model gives `inMinutes`, a local `date`/`time`, or `meetingId` + `minutesBefore`; never a timestamp (a model once stamped a UTC start's digits with the local offset), never computed instants; the server converts with `zonedInstant` (agent/time.ts). With no time at all it **asks** whether the note should show up at a time; `withoutTime: true` saves a plain note only when the person said so. `removeTime` turns a timed note back into a plain one. Cancelling is a `write` (reversible), not `destructive`. `/privacy` doesn't yet mention notes reaching the model (deferred by the owner).
  - Tests: `supabase/tests/reminders.sql` (local only, rolls back) and `npm run test:reminders`.
